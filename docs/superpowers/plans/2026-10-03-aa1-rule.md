## 0. How AA1 is switched on

- Coordinates: vertex position = `(XYZ - XYOFFSET) / 16` as float (`RSW:22`, `RSW:233,276`).
  Pixel `X` has its sample at the integer `X` (no half-pixel offset in the SW renderer).
- `IsCoverageAlpha()` = `AA1 && primclass in {LINE, TRIANGLE}` (`ST:6780-6783`); the SW renderer
  always "supports" it (`RSW:1426-1428`). Sprites/points ignore AA1 for coverage.
- `IsOpaque()` returns false whenever `AA1` is set, before looking at `ABE` (`ST:6733-6734`). So the
  `!IsOpaque()` block runs: `sel.abe = PRIM.ABE` (0 here), `sel.ababcd = ALPHA` register **as is**
  (`RSW:1288-1289`), `sel.pabe = PABE` (`RSW:1291-1294`), `sel.aa1 = 1` (`RSW:1296-1299`),
  `afix = ALPHA.FIX << 7` (`RSW:1301`).
- `sel.rfb` (read the frame) is set when any of A/B/C/D selects `Cd`/`Ad` (`RSW:1305-1313`).
- `SetupDraw` builds a second scanline function, the "edge" variant: same selector with
  `zwrite = 0, edge = 1` (`DS:133-148` JIT, `DS:172` + `DS:1761-1767` C path). `HasEdge()` is
  "the edge function exists" (`RAS.h:89`).
- The bbox grows by 1 on every side for AA1 lines/triangles (`RSW:366-369`), then +1 for exclusive
  right/bottom (`RSW:371`). The bbox only feeds the page lists and the "needs scissor test" flag
  (`RSW:373-376`, `RAS:151`); it decides **no** pixel. Which pixels are written is decided in `RAS`.

## 1. Which pixels an AA1 primitive writes

### 1a. Triangles: interior + edge pixels

**Interior.** Unchanged by AA1: drawn first, by the normal span path, with the normal
`draw_scanline` (Z write as usual) (`RAS:758-793` AVX2, `RAS:960-995` SSE). Spans: for an integer
row `Y` in `[ceil(ytop), ceil(ybottom))`, pixels `X` in `[ceil(xl(Y)), ceil(xr(Y)))`
(`RAS:720-723`, `RAS:846-861`), i.e. sample `(X,Y)` inside with a top-left rule on integer samples.
Triangles with all three y equal, or zero cross product, return before both interior and edges
(`RAS:717-718`, `RAS:734-737`).

**Edge pixels.** Then, for the same triangle, the three edges are walked in this order:
`v0→v1`, `v0→v2`, `v1→v2` (vertices y-sorted, `v0` top) (`RAS:827-829` / `RAS:1029-1031`), and the
collected pixels are flushed through the edge function (`RAS:831` / `RAS:1033`, `RAS:1410-1419`).

Per edge `a→b` (`RAS:312-469`, dispatch `RAS:629-640`):

- Major axis: `step_x = |dx| >= |dy|` (ties go to x); `pos_x = dx >= 0`, `pos_y = dy >= 0`
  (`RAS:631-633`). Zero-length edge: nothing (`RAS:321-322`).
- `side` = which side is outside: `side = tl XOR (step_x && dy != 0 && pos_x == pos_y)`;
  true means "outside is toward top/left" (`RAS:635-637`).
- `tl` (top-left flag) per edge: `tl0 = (y0 == y1) || !cw`, `tl1 = cw`, `tl2 = (y1 != y2) && !cw`,
  `cw` = sign of the cross product (`RAS:797-801`).
- Major-axis range, one pixel beyond each end: for the positive direction
  `start = ceil(a - 1)`, `end = floor(b + 1)`; mirrored for negative (`RAS:329-337`).
- Pixel filter (all must hold, `RAS:429-432`):
  - inside the **other two** edges' half-planes. Each edge function is integer, built from the
    12.4 positions: `f(X,Y) = 16*dy_s*X - 16*dx_s*Y + (x1_s*y0_s - x0_s*y1_s)` with `_s` = 1/16
    units (so `f` is a cross product in 1/256 px²), negated for clockwise so inside is positive,
    `+1` when that edge is top-left; test is `f > 0` (`RAS:803-825`, `RAS:370-371`, `RAS:429`).
    Edge `v0v1` tests `f1,f2`; `v0v2` tests `f2,f0`; `v1v2` tests `f0,f1` (`RAS:827-829`).
  - x in `[floor(min xa,xb), ceil(max xa,xb)]` (not widened), y in
    `[ceil(min y - 1), floor(max y + 1)]` (widened by 1), both clamped to the scissor, inclusive
    (`RAS:342-351`). PCSX2 says the x bound is an arbitrary pick, the GS sometimes allows ±1
    (`RAS:339-341`).
- Exactly **one** pixel per major-axis step (the minor-axis DDA below picks it), `pixels = 1`
  (`RAS:437`).

The pixel picked is the **first pixel on the outside of the edge** along the minor axis
(derivation in §2): with `d` = (edge's minor coordinate at this major step) − (nearest pixel
centre `m`), `d ∈ [-0.5, 0.5)`:

| `d` | `side` true (outside = −minor) | `side` false (outside = +minor) |
|---|---|---|
| `d > 0` | pixel `m`, cov `1 - d` | pixel `m + 1`, cov `d` |
| `d < 0` | pixel `m - 1`, cov `-d` | pixel `m`, cov `1 + d` |
| `d == 0`, `tl` | pixel `m - 1`, cov 0 | pixel `m + 1`, cov 0 |
| `d == 0`, not `tl` | pixel `m`, cov 1 | pixel `m`, cov 1 |

(`RAS:408-427`.) In every case `cov = 1 - (minor-axis distance from that pixel's centre to the
edge)`. Edge pixels are therefore disjoint from the triangle's own interior pixels (the pixel is
outside the edge, or on a non-top-left edge which the fill rule excludes); they land on the
neighbour's area.

### 1b. Lines: no interior, two pixels per major step

`DrawLine` → `DrawEdgeLine(..., HasEdge())` → `Flush(..., edge = HasEdge())` (`RAS:653-667`).
With AA1 **every** line pixel goes through the edge function (`RAS:1410-1419`).

Per segment `v0→v1` (each segment of the strip independently; strips are expanded to index pairs,
`RAS:173-190`) (`RAS:471-627`, dispatch `RAS:642-649`):

- Major axis, signs: as triangles (`RAS:644-646`).
- Endpoints round to the nearest pixel, half up: `r = floor(p + 0.5)` (`RAS:485-488`).
- Diamond-exit rule (`RAS:490-520`). With `(ex, ey)` = endpoint − its rounded pixel,
  `T(ex,ey)` = false if `|ex|+|ey| < 0.5`; else, for an x-major line,
  `T = (ex strictly in the travel direction) && (|ex|+|ey| > 0.5 || ey >= 0)`
  (y-major: swap roles, tie-break on `ex >= 0`) (`RAS:491-505`).
  First pixel drawn iff `!T(start)`, else start moves one pixel along the travel; last pixel drawn
  iff `T(end)`, else end moves back one (`RAS:507-520`). Empty range → nothing (`RAS:522-523`); a
  zero-length segment always ends here.
- For each major step from start to end inclusive (`RAS:588-624`):
  - main pixel `(major, m)` with cov `1 - |d|`;
  - neighbour `(major, m + s)` with `s = +1` if `D >= 0` else `-1`, cov `|d|`
    (`RAS:590-598`). The neighbour is emitted even when `d == 0` (cov 0, at `m + 1`).
  - Each pixel is kept if inside the scissor (exclusive right/bottom) (`RAS:571-586`). No bbox,
    no other test.

Strip joints: the start rule is the negation of the end rule, so a shared vertex is drawn once
when both segments travel the same octant direction; with a direction change it can be drawn
twice or not at all, and neighbour pixels around a joint can be written by both segments.

## 2. How coverage is computed

Decision variable, integer, exact from 12.4 inputs (`RAS:359-365`, `RAS:540-546`):

- `scaleD = int(512 * |d_major|)`, `dD = int(512 * d_minor)`, `D0 = int(scaleD * (minor0 - rminor0))`
  where `rminor0` is the rounded/starting minor pixel. With 1/16 inputs, `scaleD` = 32 × (major delta
  in 1/16 units) and `dD` = 32 × (minor delta in 1/16), all products exact.
- Prestep to the first major pixel: `D += int(dD * prestep)`, `prestep = |rmajor0 - major0|`
  (`RAS:381-384`, `RAS:558-561`), then normalise: while `D >= scaleD/2` step minor +1 and
  `D -= scaleD`; while `D < -scaleD/2` step minor −1 and `D += scaleD` (`RAS:386-390`, `RAS:563-567`,
  `StepDependent` `RAS:373-379`).
- Each major step: `D += dD`, then one conditional minor step in the line's direction
  (`RAS:447-465`, `RAS:607-623`). So `D ∈ [-scaleD/2, scaleD/2)` always, and
  `d = D / scaleD` is the exact signed distance (in pixels, along the minor axis) from the pixel
  centre `m` to the true edge/line at this major coordinate.
- Closed form, useful for a shader: with `n` = number of major steps from the first pixel,
  `Draw = D0 + int(dD*prestep) + n*dD`, `k = floor((Draw + scaleD/2) / scaleD)`,
  `m = rminor0 + k`, `D = Draw - k*scaleD`.

Coverage value (16 bits):

- Triangle: `d = float(D)/float(scaleD)`; `cov16 = int(65535 * f(d))` with `f` from the table in
  §1a (`1.0 - d` is computed in double, `65535 * d` in float), clamped to `[0, 0xffff]`
  (`RAS:396`, `RAS:408-427`, `RAS:439`).
- Line: `covi = clamp(int(65535.0f * |float(D)/float(scaleD)|), 0, 0xffff)`; main pixel
  `0xffff - covi`, neighbour `covi` (`RAS:592-597`).
- `cov16` is stored in the low 32 bits of the edge vertex's `p.x` (`RAS:439`, `RAS:582`).

To alpha: `cov = cov16 >> 9`, a 7-bit value **0..127**, broadcast to every 16-bit lane
(`DS:566-572`; JIT `CG:771-784` and the `temp.cov` use at `CG:2245-2248`). Interior pixels use
the constant `0x80` (`DS:1225-1227`; JIT `CG:2251-2253`). So an edge pixel never reaches 0x80, and
an interior pixel is exactly 0x80.

## 3. Colour path with ABE = 0

Order in the pixel pipeline: texture + TFX → **AA1 alpha replace** → alpha test → colour TFX →
fog → read frame → DATE → Z write → **blend** → frame write (`DS:1196-1237`, `DS:1254`,
`DS:1259-1300`, `DS:1302-1318`, `DS:1384-1449`, `DS:1451-1574`, `DS:1576-1672`). JIT comment:
"anti-aliasing after tfx, before tests, modifies alpha" (`CG:2237`).

1. Alpha replace (`DS:1223-1237`, `CG:2235-2281`):
   - `ABE = 0`: `As := cov` (edge) or `0x80` (interior), **unconditionally**: the vertex/texture
     alpha is discarded (`DS:1229-1232`, `CG:2241-2256`).
   - (`ABE = 1`, for reference: `As := cov` only where `As == 0x80`, else kept, `DS:1233-1236`.)
2. Alpha test sees the replaced alpha (`DS:1254`). The clock passes have `ATE = 0`.
3. Blend is **forced on**: the condition is `abe || aa1` (`DS:1453`; JIT `CG:2637-2640`), with
   A/B/C/D/FIX taken from the context `ALPHA` register as it stands (`RSW:1289`, `RSW:1301`), even
   though ABE is 0. Per channel (`DS:1473-1507`):
   `Cout = ((A - B) * C) >> 7 + D`, where `>> 7` is an arithmetic floor:
   `modulate16<1>` = `((x << 2) * (C << 7)) >> 16` signed (`V4:1010-1015`, `DS:1493-1498`).
   `C = As` → the replaced alpha (cov or 0x80) (`DS:1493`).
   If `A == B`: `Cout = D` (`DS:1508-1516`). With `PABE`, pixels whose `As` bit 7 is 0 keep `Cs`
   (`DS:1518-1523`) — every edge pixel (`cov <= 127`) would then be unblended; clock `PABE = 0`.
4. Clamp: `COLCLAMP = 1` saturates 0..255, else `& 0xff` (`DS:1588-1592`).
5. Frame alpha: after the blend, the alpha lane is restored from the source (`ga.mix16(gas)`,
   `DS:1563-1573`), so **the frame alpha written is the replaced alpha: 0x80 on interior pixels,
   `cov16 >> 9` on edge pixels** (subject to `FBA` setting bit 7, `DS:1596-1599`, and `FBMSK`,
   `DS:1609-1612`). For PSMCT24 the alpha byte is kept (`DS:481`).

Consequences for the clock:

- Rod refracted faces, `ALPHA 0x44` `(Cs - Cd) * As + Cd`: interior = `((Cs-Cd)*128 >> 7) + Cd = Cs`
  exactly (no blend visible); edge pixel = `floor((Cs-Cd)*cov/128) + Cd`, a real coverage blend
  over whatever is in the target. Frame alpha: 0x80 interior (not the texel/vertex alpha), cov on
  the outside ring.
- Orb trail, `ALPHA 0x48` `(Cs - 0) * As + Cd`: there is no interior, so every pixel is
  `Cd + floor(Cs * cov / 128)`, i.e. **additive**, weighted by coverage: main pixel ≈
  `Cs*(1-|d|)`, neighbour ≈ `Cs*|d|`, the pair summing to just under `Cs`. The vertex alpha
  (`fade/2`) has no effect. Frame alpha is overwritten with the coverage, including 0 on a
  neighbour pixel with `d == 0`.
- Pass 4/5 or any later pass reading `Ad` or a texture alpha from these targets sees these values.

## 4. Depth on edge pixels

- Tested: the edge selector is a copy of the draw's selector with only `zwrite` and `edge` changed
  (`DS:137-139`, `DS:1763-1765`), so `ztest`/`ztst` stay. The Z compared is the edge vertex's Z
  (`DS:548-561`; no per-pixel step since edges flush with `dscan = 0`, `RAS:831`, `RAS:1394`).
- Written: **never** (`zwrite = 0`, `DS:138`, `DS:1764`). For AA1 **lines** this means no Z is
  written by any pixel of the line, since all line pixels are edge pixels (`RAS:664`). Triangle
  interiors write Z normally.
- Edge attributes: the edge vertex starts at `a`, steps by `dv / |d_major|` per major pixel, with
  the same prestep (`RAS:353-355`, `RAS:381-383`, `RAS:448`; lines `RAS:534-536`, `RAS:558-560`,
  `RAS:608`). So colour, Z, fog, STQ/UV are the values **on the edge line at that major
  coordinate**, not at the pixel's centre; at the extra pixel beyond each end they are
  extrapolated. Then `ClampVertex`: colour and fog saturated to `[0, 255*128]`, Z clamped to
  `[0, 2^24-1]` or `[0, 2^32-1]` by `ZBUF.PSM` (`RAS:300-309`, called `RAS:437`, `RAS:579`).
  Texture coordinates are not clamped there; the texture wrap mode (REGION_CLAMP here) applies.
- Flat shading: the scanline takes `iip ? interpolated : flat` (`DS:1219`, `DS:1277`); the flat
  value comes from `CSetupPrim` (per primitive, not read in detail here), not from the edge vertex.

## 5. Order

- Per triangle, strictly: interior spans, then edge pixels of `v0v1`, `v0v2`, `v1v2` in DDA
  order; then the next triangle (`RAS:793-831`, `RAS:194-212`). One triangle's edge pixels lie
  on the neighbour's area, so in a strip/mesh: triangle N's outer ring along a shared edge is
  then overwritten by triangle N+1's interior (Z permitting; the ring wrote no Z); triangle N+1's
  ring along the same edge blends over triangle N's interior.
- Within one triangle a pixel can be an edge pixel of two edges (near sharp vertices); it is then
  blended twice, in the order above.
- Lines: segment by segment in index order, main pixel then neighbour per major step
  (`RAS:596-597`); pixels shared between segments are blended once per segment.
- Threads split work by rows (`IsOneOfMyScanlines`, `RAS:74-79`) and keep per-row order, so the
  result is the sequential order above. `SCANMSK` applies to edge pixels too (`RAS:1446`).
- `GSRasterizer::DrawEdge(v0, v1, dv, orientation, side)` (`RAS:1181-1378`) is an older edge
  walker with no caller in this version.

## 6. Vulkan design (pixel-interlocked storage-image renderer)

Inputs per primitive: the GS 12.4 positions. Floats in pixels are exact multiples of 1/16, so
recover `xs = int(round(x*16))` and do all edge math in integers.

### Lines (orb trail)

- One instance (two triangles) per segment; segment data (12.4 endpoints, Z, flat colour) in a
  storage buffer indexed by `gl_InstanceIndex`/`gl_PrimitiveID`. Vertex shader emits a rectangle
  covering major range `[start-0.5, end+0.5]` (after the diamond rule, computed per segment in the
  vertex shader or on the CPU) and minor range `line ± 2` px, in GS pixel space mapped to Vulkan
  centres.
- Fragment `(X, Y)`: `n = (X_major - start) * dir`; closed-form `D`, `k`, `m` (§2); keep the
  fragment iff `Y_minor == m` (cov `1-|d|`) or `Y_minor == m + (D >= 0 ? 1 : -1)` (cov `|d|`);
  otherwise discard before the interlock. Use 64-bit integers or divide `scaleD`, `dD`, `D0` by
  their common factor 2 first (`scaleD`, `dD` are multiples of 32, `D0` of 2) to stay in int32.
- Inside the interlock: Z test (GREATER) against the edge Z
  (`z0 + (z1-z0) * (n + prestep)/|d_major|`, clamped), **no Z write**, blend with `ALPHA` A/B/C/D
  and `As = cov16 >> 9`, write frame alpha = `cov16 >> 9`.
- Two quad triangles of one segment never cover a pixel twice; ordered interlock then gives
  segment order per pixel.

### Triangles (rod refracted faces)

Two equivalent layouts; both exact if the fragment logic is exact.

- A. One draw, per GS triangle seven Vulkan triangles in order: the triangle itself (interior,
  GS fill rule), then three edge quads (`v0v1`, `v0v2`, `v1v2`, y-sorted), each a thin quad
  spanning the edge's major range `[ceil(a)-1, floor(b)+1]` × `edge ± 1.5` px. Ordered interlock
  follows primitive order, which matches PCSX2's interior-then-edges-then-next-triangle order.
- B. One expanded primitive per GS triangle (triangle offset outward by ≥ 1.5 px, or its bbox
  +1 px) whose fragment decides: interior (GS fill rule) → interior shading; else, in order
  `v0v1`, `v0v2`, `v1v2`, if this pixel is that edge's DDA pixel → one blend each, all inside one
  interlock section (handles the double-blended vertex pixels in order).
- Edge-pixel test in the fragment: closed-form `D`, `m`, then the §1a table (needs `tl`, `side`,
  from the triangle's y-sorted vertices and the sign of its cross product), then the bbox
  (x not widened, y widened by 1, scissor) and the two other integer edge functions `> 0` with
  the +1 top-left bias.
- Shading of an edge pixel: attributes from the edge point
  `a + (b - a) * t`, `t = (X_major - a_major) * dir / |d_major|` (can be < 0 or > 1), colour/fog
  clamped, then the normal texture path (UV for FST, region clamp, bilinear), TFX, then
  `As := cov16 >> 9`, blend with the `ALPHA` register, frame alpha `cov16 >> 9`, Z test with the
  edge Z, no Z write.
- Interior pixels of an AA1 triangle: `As := 0x80`, blend forced with the `ALPHA` register (for
  `0x44` that is `Cs`), frame alpha written 0x80, Z written as usual.

### Must be exact

- The set of edge pixels: integer DDA (`D`, normalisation to `[-scaleD/2, scaleD/2)`), the
  major range one pixel past each end, the `tl`/`side` table including `d == 0`, the line
  endpoint diamond rule and the always-emitted line neighbour, the other-two-edge-function test,
  the asymmetric bbox.
- Alpha: `cov16 >> 9` (0..127) on edges, 0x80 on interiors, discarding the source alpha when
  ABE = 0.
- Blend forced on with the `ALPHA` register for AA1 even with ABE = 0; floor `>> 7` on signed
  `(A-B)*C`; COLCLAMP.
- Frame alpha written = that alpha (0x80 / cov).
- Z: tested on edge pixels, never written by edge pixels, never written by AA1 lines.
- Order per pixel: triangle interior, its edges `01, 02, 12`, then the next triangle; line
  segments in order.

### May be approximated (measure in slice 0)

- The float steps of the coverage: PCSX2 computes `D/scaleD` in float and `65535*(…)` in
  float/double, then truncates. An integer `65535*|D| / scaleD` (or GPU fp32, whose division is
  not correctly rounded) differs by at most ~1 in `cov16`, which changes `cov16 >> 9` only when
  it sits on a multiple of 512: rare ±1 in alpha on isolated pixels.
- Edge attributes (colour for IIP, UV/STQ, Z) evaluated in float instead of PCSX2's
  float/double stepping. Z is the risky one: an equal-depth GEQUAL/GREATER comparison on an edge
  pixel can flip; keep Z interpolation in the same `z0 + dz*t` form, with `t` from integers.
- Interior spans: PCSX2 uses float edge stepping with `ceil`; the integer edge-function fill used
  for the edge-pixel tests can disagree with it on rare exact-boundary rows. That is the
  renderer's existing triangle-edge question, not new to AA1.
